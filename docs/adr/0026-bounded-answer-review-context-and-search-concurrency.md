# ADR-0026: Bounded answer self-review, context selection and search concurrency

- Status: Accepted for implementation; semantic quality/default promotion pending
- Date: 2026-10-02
- Related: ADR-0008, ADR-0022, ADR-0024, ADR-0025

## Context

Retrieval improvement does not establish supported answers or complete coverage. The runtime checked citation IDs but had no bounded claim-review/repair phase. Saved conversations could fill a provider context indefinitely, and asynchronous local queries ran serially. The owner requested these gaps be addressed in order while continuing to defer paid Agent/judge/E2E validation.

## Decision

1. Keep five read-only evidence tools. Add host-owned answer review and coverage state, rather than a sixth planning tool. Structural citation delivery/freshness checks remain the default and make no additional model calls. Opt-in `self-review` uses the same answer provider/model; its setting and UI explicitly describe added billed calls and the absence of independent verification.
2. Reserve three of the existing ten requests for a first review, at most one revision, and a second review. Share the existing tool-call/output budgets. Buffer drafts and thinking in this mode. Review every preselected paragraph, heading, list item and table row, including uncited opening claims, using a strict bounded JSON schema. Review covers at most 64 units and eight question parts. Scope/quote/selector checks are deterministic; entailment, classification and semantic completeness remain model judgments.
3. Supply only actually delivered evidence, with 24k source characters total and a disclosed 4k prefix per exposure. Do not expand a ledger ID to an unseen body. Track all delivered citation identities separately from this reviewer text cap, so structural checks do not mistake clipping for absence. Exact quotes must occur in an allowed, cited source scope. Stale citations require current reads. Absence needs an exhausted, exact, error-free query scope. General knowledge and inference must be labeled, with that labeling assessed by the reviewer.
4. Represent each required question part as answered, partial, missing or conflicting. Unresolved parts can end research only when explicitly disclosed in identified answer units. Allow at most three schema-validated targeted searches or reads, including bounded read continuation/section selection. Repair actions are recorded as host-initiated synthetic tool calls with matching results, not forged provider raw responses. Never permit writes. Invalid reviews, cancellation, exhausted requests or a failed second review do not publish an unchecked draft. Keep rejected drafts, raw reviewer responses and issues for audit and append a rejection notice to conversation history.
5. Keep full saved history and signed/encrypted raw assistant content unchanged. Select complete historical human turns for each request, newest first; never split a call/result pair. Use a conservative UTF-8 byte input allowance of 64k by default, explicitly not a tokenizer/billing estimate. Account for the larger neutral/raw assistant representation and exclude duplicate local delivery metadata. Bound encoded tool output against remaining request space. If the current turn itself cannot fit, stop with a clear message before sending it.
6. Replace omitted history with a bounded extractive navigation index of recent old question prefixes and archived evidence identities, not generated factual summaries. Treat all entries as quoted data. Archived IDs need new source reads; changed/deleted source hashes are disclosed. Full historical decisions remain saved; automatic semantic memory is not claimed. Persist context diagnostics and review/coverage state in optional fields compatible with old conversation records.
7. Prepare at most two contiguous independent search calls concurrently. Await both preparations before delivery, then render/register/account for results in model order. Reads, graph operations and ledger writes remain serial. No new preparation starts beyond the applicable call/output limits. Corpus revision checks, transactional registration and matched cancellation results preserve the original delivery boundary.
8. Freeze a separate synthetic suite for long sections, Chinese requests, conflicts, note instructions and changed sources. Prepare a versioned paired evaluation of BM25, hybrid and hybrid plus self-review, with shared answer/judge configuration, rotating execution order, bounded shared spending, raw recordings, failure denominators and independent human review pending. A separate explicit phase flag prevents an existing live evaluation environment from dispatching this new phase accidentally. Never overwrite prior runs. Previously-used test questions remain regression data; new synthetic cases are not human gold or a fresh owner-workload holdout.

## Consequences

The runtime can now collect bounded review/coverage state, repair once, and refuse to deliver failed drafts. It cannot guarantee semantic truth: same-model self-review is fallible and extra calls may increase cost/latency. Source caps can require narrower reads or explicit gaps. Structural mode does not provide semantic review.

Long conversations have a request window while their audit history remains complete. Archived decisions may require clarification; no automatic semantic memory or tool parallelism beyond query preparation is introduced. Historical SDK recording tests use an explicit 512k byte allowance to preserve old signed-block exchanges; separate tests enforce today's default/window behavior.

Free unit checks and actual fixture-vault Obsidian tests use scripted answer models; local embedding tests use genuine Ollama vectors. These prove mechanics, not live answer quality or model injection resistance. Paid paired evaluation, live-provider E2E, independent human calibration and fresh representative question collection remain deferred. BM25 and structural checks remain defaults; no vector database or extra planner tool is justified by this phase.

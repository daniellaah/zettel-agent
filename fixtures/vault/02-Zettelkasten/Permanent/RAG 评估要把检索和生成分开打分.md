# RAG 评估要把检索和生成分开打分

一个 RAG 系统答错了，可能是根本没检索到相关内容，也可能是检索到了但生成时没用好。只看最终答案，会把这几种失败混在一起，改进时就不知道该动哪一层。

我的做法是分两层打分。检索层：人工标注每个问题的相关笔记，计算 recall@k 和 MRR，看相关内容有没有被召回、排在第几。生成层：检查每条引用是否真的支持它所在的句子（faithfulness），答案是否覆盖了问题的所有部分。

另外专门放一批"库里没有答案"的问题，检查系统会不会编造；再放几条跨语言的问题，检查中英文混写的笔记能不能互相找到。

评估集要小而准：四十条人工核对过的问题，比一千条自动生成、没人看过的问题有用得多。

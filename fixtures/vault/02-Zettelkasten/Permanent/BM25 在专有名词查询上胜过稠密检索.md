# BM25 在专有名词查询上胜过稠密检索

在我的笔记和代码搜索里，很多查询其实是专有名词：函数名、论文缩写、人名，或者 "LogQ"、"Swing" 这种圈内词。

稠密检索（dense retrieval）把查询映射到语义空间，这些词会被语义上相近但并不相同的词淹没——搜 "Swing" 返回一堆讲"相似度"的笔记。BM25 做精确的词项匹配，再加上 IDF 让稀有词权重很高，在这类查询上反而更稳。推荐系统里只靠向量召回、长尾 ID 召不回来，是同一个现象。

反过来，同义改写和跨语言查询是 BM25 的短板：用"间隔重复"去搜，找不到只写了 spaced repetition 的笔记。所以 BM25 不是该被淘汰的 baseline，而是混合检索里必不可少的一路。

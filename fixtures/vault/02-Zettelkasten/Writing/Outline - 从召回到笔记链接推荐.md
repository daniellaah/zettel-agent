# Outline - 从召回到笔记链接推荐

想写一篇博客：把推荐系统里 i2i 召回的思路搬到卡片盒里，用来推荐"应该存在但还没建立"的链接。

1. 开头：卡片盒里的链接为什么会缺失（写卡片时没想到、旧卡片早就忘了）
2. 推荐系统里的 i2i
   - 共现为什么有噪声
   - [[Swing 相似度惩罚热门共同用户]] 的思路：对"什么都点"的用户降权
3. 卡片盒里的"共现"
   - [[共同被引用的笔记值得直接链接]]
   - hub 笔记（索引、MOC）等价于"什么都点"的用户，应该降权
4. 怎么评估链接推荐
   - 留出一部分已有链接当正样本，看能不能召回：[[Recall@k 只衡量候选集而非最终排序]]
   - 但最终还是要人工判断每条推荐能不能写出理由
5. 结尾：推荐只给候选，链接理由必须人写

待补：第 3 节缺一个具体例子。

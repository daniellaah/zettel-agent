# Draft - 为什么我的卡片盒需要一个研究 agent

## 问题

### 搜索只能找到我记得的词
全文搜索的前提是我记得当时用了哪个词。可我的笔记中英文混写：同一个概念，有的卡片写"召回"，有的写 retrieval，有的写 recall。搜一个词，只能找到三分之一。

### 链接网络越大越难走
卡片盒的价值在链接里（见 [[卡片盒是对话伙伴而非存档]]），但卡片过了几百张之后，我已经没有耐心顺着链接走三层以上。很多有价值的连接其实就在两跳之外，我从来没走到。

## 方案

### 检索层
#### 稀疏一路
专有名词多，BM25 必须保留，原因见 [[BM25 在专有名词查询上胜过稠密检索]]。参数先用默认值，k1 的意义记在 [[Lit - Robertson Zaragoza BM25#k1：词频饱和]]。

#### 链接图一路
从检索命中的卡片出发，沿着链接扩展一到两跳，把邻居也作为候选。

#### 融合
两路用 [[RRF 融合只依赖排名不依赖分数|RRF]] 合并，不做分数校准。

### Agent 层
agent 本身就是一个循环，重点在[[Agent loop 的质量取决于工具设计|工具设计]]：搜索、按节读取、沿链接扩展，三个工具就够。上下文预算要严格控制，参考 [[Context engineering is choosing what the model does not see]]。

### 引用与只读
每个结论都要带上来源卡片的路径和标题。agent 只读，不改任何笔记——我不想让它替我写卡片，那会破坏"用自己的话写"的前提。

## 评估

### 检索指标
人工标注四十条问题，按 [[RAG 评估要把检索和生成分开打分]] 的思路，检索层单独算 recall@k。

### 回答质量
看引用是否支持结论、无答案的问题是否老实说"没找到"。
